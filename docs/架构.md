# 架构

> 2026-11-17 起，后端是 Node/TypeScript + cordis（`server/`）。
> 旧 Python/FastAPI 实现已删除；现在只有 `server/` 一套运行时。
> 迁移过程与取舍见 [cordis迁移.md](cordis迁移.md)。

## 1. 分层

```
Vue 3 (frontend/)
   │  fetch /api/*
   ▼
cordis 应用 (server/src/)
   │
   ├── plugins/                 装配层：一个服务一个文件
   │     http.ts                路由、JSON、静态产物、缓存头、错误
   │     api.ts                 等 content/db/rules/server 就绪后注册 30 个接口
   │     health.ts              /api/health（装配完整性探活）
   │     content.ts             内容加载、热重载、写回
   │     db.ts（db/client）      SQLite / PostgreSQL / MySQL
   │     rules.ts               纯规则入口（检定、五行、角色卡）
   │
   ├── api/                     接口板块：archive / characters / game / sessions
   │
   ├── core/                    规则层：纯函数，不 import cordis
   │     python · dice · checks · wuxing · sheet · gacha · npc
   │     kp · mission · progress · session
   │
   ├── content/                 内容层：加载 JSON、索引、编辑校验、原子写回
   │        └── server/data/content/*.json   ★ 全部设定数据
   │
   └── db/                      持久层：三张表、方言适配、行映射
            └── server/data/moyu.db          运行库
```

三条边界：

1. **接口层不做规则**：路由只负责取数据、调引擎、拼响应。
2. **引擎不认识数据库**：`core/*` 吃 dict、吐 dict，可单独跑 vitest 与整局回放。
3. **内容不写进代码**：设定是 JSON，改文件即可，不需要改 TypeScript。

另外三条 cordis 约定：

- 依赖用 `static inject = ['content']` 声明，加载顺序由内核解析，不靠 import 顺序；
- 注册类副作用（路由、watcher、关闭钩子）都放在 `ctx.effect()` 里，插件卸载时自动撤销；
- 插件配置用 `schemastery` 导出 `Config`，由 loader 在启动时校验并填默认值。

**装配有两条路径**（L1 试点，2026-11-18）：

| 路径 | 入口 | 用途 |
| --- | --- | --- |
| 生产 | `src/index.ts` → `@cordisjs/loader` 读 `server/cordis.yml` | 有哪些插件、各自配什么由文件决定，顺序由 inject 推导 |
| 测试 | `src/app.ts` 的 `createApp()` | 随机端口、临时内容目录、临时库，不产生进程级监听 |

两条路径共用同一批插件类；代价是插件清单要同步维护（`cordis.yml` 与 `createApp`）。
长期如果继续 L1，建议测试也走 loader 的 `initial` 配置，让装配只剩一份。

## 2. 一次请求的链路

以「开一桩随机任务」为例：

```
POST /api/sessions/random {character_id, city}
  → api/sessions.ts       查角色、校验城市
  → core/mission.ts       city + 2~3 条事件 + 一只祟物 → 场景流
  → core/session.ts       newState() 初始化气血/灵力/理智/阴浊
  → db/repo.ts            sessions.state 存 JSON 列；场景流一起存进 state["scenario"]
  ← {id, code, mission_id, name, difficulty, reward}
```

场景流存进会话状态，是因为随机任务的剧本不在 `scenarios.json` 里，
重进这一局要靠它复现。

## 3. cordis 服务

| 服务 | 文件 | 职责 | 依赖 |
| --- | --- | --- | --- |
| `ctx.content` | `plugins/content.ts` | 持有 JSON 索引；reload；写回 | — |
| `ctx.db` | `db/client.ts` | 连接、迁移、事务、方言适配 | — |
| `ctx.rules` | `plugins/rules.ts` | 检定、五行、角色卡计算 | `content` |
| `ctx.server` | `plugins/http.ts` | 路由、静态产物、统一错误 | — |
| `ctx.api` | `plugins/api.ts` | 注册 30 个接口 | `server` `content` `db` `rules` |

`core/*` 不依赖 cordis；`api/*` 只依赖服务，不 import 具体实现。
这样规则可以脱离 Web 单测，接口也可以只换 HTTP 层。

HTTP 层是自研的约 250 行 `node:http` 服务，没有用 `@cordisjs/plugin-server`：
后者 1.7.0 与 cordis rc.12+ 不兼容（`Service.resolveConfig` 被移除），
而后端需要的路由/JSON/静态能力很少，自己写反而可控。

## 4. 内容层

- 数据文件：`server/data/content/*.json`（world / events / traits / missions / talismans
  / spirits / bestiary / equipment / shop / scenarios）。
- 加载：`content/store.ts` 按 mtime 缓存、抛 `ContentError`；
  `content/index.ts` 把每个文件转成「数组 + id 索引 + 纯函数」。
- 热重载：`POST /api/admin/reload` 强制重读全部文件，返回每个文件的状态；
  文件监听会广播 `content/reload` 事件。
- 写回：`content/edit.ts` 逐字段校验、跨文件引用校验、删除前查数据库引用；
  `content/write.ts` 用「同目录临时文件 + fsync + rename」原子写回。

改设定的流程：编辑 JSON → 调 reload → 刷新页面。不用重启进程。
档案页的 11 类增删改也走同一条路：编辑 → 校验 → 原子写回 → 自动重载。

### 内容索引

每个模块导出 `indexXxx(doc)`（建 Map）与纯函数，例如：

```ts
const world = indexWorld(doc)                 // Map: cityById / tierByKey ...
tierRank(world, city.tier)                    // 越小越大
eventPool(events, world, city, missionId)     // 带权事件池
```

迁移前的模块级全局被换成了「一个 ContentData 对象」，reload 时整体替换，
不会再出现 `from ... import TRAITS` 拿到旧值的问题。

## 5. 持久层

- 只存**会变的东西**：角色、会话、日志。设定不进库。
- 三张表：`characters` / `sessions` / `session_logs`；JSON 列在 SQLite 是 TEXT，
  在 PostgreSQL 是 JSONB，在 MySQL 是 JSON。
- 驱动：
  - SQLite：Node 内置 `node:sqlite`，零原生依赖；打开 `foreign_keys` 与 WAL；
  - PostgreSQL：`pg`；MySQL：`mysql2`。业务 SQL 统一写 `?`，适配层转换成 `$n`。
- 迁移：启动时执行对应方言的 `schema.*.sql`（`CREATE TABLE IF NOT EXISTS`），
  并用 `user_version` / 信息模式补 `rules_version` 列。
- 时间列是 TEXT（`YYYY-MM-DD HH:MM:SS.ffffff`），三个方言共用一套读写代码。

规则版本：`sessions.rules_version` 记录开局时的规则版本；当前版本是 1。
按 2026-11-17 的决定，规则热更**只影响新开的局**，旧局按记录版本继续跑。

## 6. 接口板块

```
server/src/api/
  index.ts       聚合 registerAll
  schemas.ts     zod 请求体
  common.ts      人物摘要、城市视图、请求体解析
  archive.ts     世界/事件/任务/装备/特性/剧本 + 内容热重载 + 11 类档案增删改
  characters.ts  名录/生成/自建/角色卡/成长线
  game.ts        总览/地图/城市面板
  sessions.ts    开团/取状态/行动
```

约定：每个模块导出一个 `registerXxx(ctx)`，`plugins/api.ts` 只做一次装配。
错误统一是 `{detail: "中文原因"}`；编辑/校验失败是 400，找不到是 404。

30 个接口的清单见 [接口.md](接口.md)。旧 FastAPI 的 Swagger 页没有搬过来。

## 7. 前端

TypeScript + Vue 3，`npm run build` 出产物，`npm run typecheck`（vue-tsc）做类型检查。
后端换语言没有动前端：所有数据仍然只从 `/api` 来，类型集中在 `src/shared/types.ts`。

```
src/
  main.ts            挂载入口
  env.d.ts           vite/client 类型 + __BUILD_ID__ 声明
  app/               壳：不属于任何路由
    App.vue          顶栏 + router-view + 设置面板 + 遮掩层 + toast
    router.ts        首页 / 档案 / 游戏 / 角色 / 建卡 / 处置台
    TopBar·SettingsPanel·StealthOverlay
  areas/             按功能分区：一个目录 = 一个功能的全貌
    HomeView
    archive/         ArchiveView · ArchiveEditor · archiveSpecs
      details/       11 个类别详情各一个组件 + index.ts 注册表
    play/            GameView · CreateView · CharacterView · PlayView
                     ChinaMap · MeterBar · EventStream
  shared/            api.ts（HTTP 薄封装 + 响应类型）· types.ts（接口模型）
                     settings.ts · stealth.ts · flash.ts
  assets/china.ts    脚本生成的中国轮廓
```

分目录的规则只有一条：**一个功能的东西都放在 `areas/<区域>/` 里**；
被第二个区域用到时才提到 `shared/`；顶栏、设置、遮掩这种全站壳放 `app/` 根下。

## 8. 遮掩（摸鱼）模式

现实约束：这个项目是拿来在工位上看小说的，所以「被人看见」是必须处理的状态。

三种模式（设置里选）：

| 模式 | 行为 | 恢复 |
| --- | --- | --- |
| 不遮掩 | 正常显示 | — |
| 模糊 | 整页 `backdrop-filter: blur(18px)`，只留「已锁定」 | Ctrl+Shift+H / Esc / 点击 |
| 伪装页 | 换成一页「订单中心运维手册」，不含任何游戏词 | Ctrl+Shift+H / Esc |

触发方式：

- 快捷键 `Ctrl+Shift+H` 随时切换（顶栏也有「◐ 遮掩」按钮）
- 切到别的窗口 / 标签页时自动遮掩（设置里可关）

几个刻意的设计：

- 伪装页只留一个不显眼的「← 返回」按钮，**不写快捷键提示**——有人站在后面时，「按 X 恢复」那行字等于自曝。
- 自动遮掩要求**先有过交互**，否则刚打开页面、窗口还没聚焦就会被盖住。
- 遮掩层是 `position: fixed; z-index: 300` 的独立层，不销毁下面的页面状态，
  恢复后还停在原来那一页、那一局。

## 9. 静态产物与浏览器缓存

重新构建前端后「页面没变」，多半是缓存问题。后端对静态产物分两种策略：

| 路径 | 响应头 | 理由 |
| --- | --- | --- |
| `index.html` 及 SPA 兜底 | `Cache-Control: no-store` | 它引用带 hash 的 JS/CSS，一旦被缓存就会一直加载旧 bundle |
| `/assets/*` | `public, max-age=31536000, immutable` | 文件名带内容 hash，内容变了名字就变，可以永久缓存 |

另外构建时会把时间戳（本地时区）写进产物，设置面板底部能看到「构建版本」，
用来确认当前页面到底是哪一次构建。

实现：`server/src/plugins/http.ts` 的 `serveStatic` / `sendFile`。
SPA 兜底只对非 `/api` 路径生效，未知接口仍然是 JSON 404。

## 10. 为什么从 FastAPI 迁到 cordis

一句话：想要「只装一个 Node」、前后端同语言，并且给规则/内容留插件化的余地。

- 引擎是纯函数、内容是 JSON、接口是薄层，结构上适合平移；
- 最硬的随机数复现问题已经用「CPython `random.Random` 逐位兼容」解决，
  旧种子与新种子都能算出同一串数；
- 代价是后端重写，以及 cordis 4.x 仍是 RC。完整评估、阶段记录与风险见
  [cordis迁移.md](cordis迁移.md)。
