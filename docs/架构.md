# 架构

## 1. 分层

```
Vue 3 (frontend/)
   │  fetch /api/*
   ▼
FastAPI (backend/app/api/)          接口板块：路由、请求体、组装响应
   │
   ├── engine/                      规则层：纯函数，不碰 IO
   │     dice · wuxing · checks · sheet · gacha · npc
   │     kp · progress · mission · session
   │
   ├── content/                     内容层：加载 JSON、建索引、热重载
   │        └── backend/data/content/*.json   ★ 全部设定数据
   │
   └── models/                      持久层：base（引擎/会话）+ entities（三张表）
            └── backend/data/moyu.db          运行库
```

代码与数据分开：

```
backend/
  app/        代码（api / engine / content / models）
  data/       数据（content/*.json 设定、migrations、moyu.db）
```

三条边界：

1. **接口层不做规则**：路由只负责取数据、调引擎、拼响应。
2. **引擎不认识数据库**：吃 dict、吐 dict，可单独跑测试。
3. **内容不写进代码**：设定是 JSON，改文件即可，不需要改 Python。

## 2. 一次请求的链路

以「开一桩随机任务」为例：

```
POST /api/sessions/random {character_id, city}
  → api/sessions.py      取角色、校验城市
  → engine/mission.py    city + 2~3 条事件 + 一只祟物 → 场景流
  → engine/session.py    new_state() 初始化气血/灵力/理智/阴浊
  → models.PlaySession   状态存 JSON 列；场景流一起存进 state["scenario"]
  ← {id, code, name, difficulty, reward}
```

场景流存进会话状态，是因为随机任务的剧本不在 `scenarios.json` 里，
重进这一局要靠它复现。

## 3. 内容层

- 数据文件：`backend/data/content/*.json`（world / events / traits / missions / talismans
  / spirits / bestiary / equipment / shop / scenarios）
- 加载：`app/content/_store.py` 负责读、缓存（按 mtime）、抛 `ContentError`
- 模块：`app/content/world.py` 等只是「加载器 + 索引 + 纯函数」，
  暴露 `CITIES` / `CITY_BY_ID` / `get()` / `compatible()` 这类名字，引擎不用改
- 热重载：`POST /api/admin/reload` 强制重读全部文件，返回每个模块的状态；
  跨模块引用（如 `sheet.TRAITS`）通过注册回调一起刷新

改设定的流程：编辑 JSON → 调 reload → 刷新页面。不用重启进程。

## 4. 持久层

- 只存**会变的东西**：角色、会话、日志。设定不进库。
- JSON 列用 `JSON().with_variant(JSONB(), "postgresql")`：SQLite/MySQL 存 JSON，PG 存 JSONB。
- SQLite 额外打开 `foreign_keys` 与 WAL，并用 NullPool。
- 迁移：Alembic，单条方言无关基线；新增非空列必须先给 `server_default` 再撤掉，
  否则老数据会撞约束（踩过一次）。
- 跨库搬运：`scripts/migrate_db.py --from <url>`，按外键顺序逐表复制。

## 5. 接口板块

```
app/api/
  __init__.py    聚合 api_router
  schemas.py     请求体（Pydantic）
  common.py      ORM→dict、列表摘要、城市视图
  archive.py     世界/事件/任务/装备/特性/剧本 + 内容热重载
  game.py        总览/地图/城市面板
  characters.py  名录/生成/自建/角色卡/成长线
  sessions.py    开团/取状态/行动
```

约定：每个模块一个 `router = APIRouter(prefix="/api", tags=[...])`，
`main.py` 只做 `app.include_router(api_router)`。

## 6. 前端

```
src/
  App.vue        顶栏 + router-view + 设置面板
  router.js      首页 / 档案 / 游戏 / 角色 / 建卡 / 处置台
  settings.js    主题、字号、动效（localStorage）
  api.js         对 /api 的薄封装
  views/         Home / Archive / Game / Character / Create / Play
  components/    TopBar / SettingsPanel / ChinaMap / MeterBar / EventStream
  assets/china.js  脚本生成的中国轮廓
```

档案页是一个由配置驱动的通用视图：左目录（11 类）→ 中列表 → 右正文，
每种类型的详情用 `v-if` 分支渲染。

## 7. 评估：要不要上 cordis

**cordis 是什么**：Koishi 生态的插件内核，核心是
`Context` + `Service`（依赖注入）+ `Plugin`（生命周期、热重载、配置 schema）。

**它擅长解决的问题**：运行时把功能拆成插件、按依赖顺序加载、热插拔、给插件配 schema 校验。

**我们的需求**：

| 需求 | 现状 | cordis 能带来什么 |
| --- | --- | --- |
| 设定可被非程序员修改 | JSON + reload 已满足 | 无 |
| 规则可扩展 | 引擎按模块划分，加规则要写 Python | 插件化能免重启，但规则本身仍要写代码 |
| 内容包分发（未来） | 未做 | 有现成模型可借鉴 |
| 多人在线（未来） | 未做 | 需要的是 WebSocket + 房间，与 cordis 无关 |

**结论：现在不换。** 三个理由：

1. 我们的「可变」是**数据**，不是**代码**。数据用 JSON 解决比插件化便宜一个量级。
2. cordis 在 JS/TS 生态。换过去意味着后端与规则引擎重写，而引擎的 101 个单测是资产，不是负担。
3. 单机单进程没有「动态装配」的压力；插件化的收益要在「多团队并行、第三方扩展」时才显出来。

**什么时候值得重新评估**：

- 如果要把后端统一到 Node（前后端同语言），cordis 的 Context/Service 很合适；
- 如果要对外提供**规则包/内容包**，让别人不改主仓库就能加内容；
- 如果要做**编辑器**（运行时加载、卸载、热更规则）。

**折中方案（已经在做）**：内容 JSON 化 + 热重载 = 数据层热插拔；
引擎按「服务」划分（骰子/检定/战斗/KP/任务），未来若要插件化，
可以加一个注册表，让规则以「包」的形式登记，而不必换生态。

## 8. 遮掩（摸鱼）模式

现实约束：这个项目是拿来在工位上看小说的，所以「被人看见」是必须处理的状态。

三种模式（设置里选）：

| 模式 | 行为 | 恢复 |
| --- | --- | --- |
| 不遮掩 | 正常显示 | — |
| 模糊 | 整页 `backdrop-filter: blur(18px)`，只留「已锁定」 | Ctrl+Shift+H / Esc / 点击 |
| 伪装页 | 换成一页「订单中心运维手册」，不含任何游戏词 | Ctrl+Shift+H / Esc |

触发方式：

- 快捷键 `Ctrl+Shift+H` 随时切换（顶栏也有「◐ 遮掩」按钮）
- 切到别的窗口 / 标签页时自动遮掩（设置里可关）

实现：

```
frontend/src/stealth.js             状态与快捷键、失焦监听
frontend/src/components/StealthOverlay.vue   两种覆盖层
frontend/src/settings.js            stealthMode / stealthAuto 持久化
```

几个刻意的设计：

- 伪装页**不给恢复提示**——有人站在后面时，一行「按 X 恢复」就等于自曝。
- 自动遮掩要求**先有过交互**，否则刚打开页面、窗口还没聚焦就会被盖住。
- 遮掩层是 `position: fixed; z-index: 300` 的独立层，不销毁下面的页面状态，
  恢复后还停在原来那一页、那一局。

## 9. 静态产物与浏览器缓存

重新构建前端后「页面没变」，多半是缓存问题。现在后端对静态产物分两种策略：

| 路径 | 响应头 | 理由 |
| --- | --- | --- |
| `index.html` 及 SPA 兜底 | `Cache-Control: no-store` | 它引用带 hash 的 JS/CSS，一旦被缓存就会一直加载旧 bundle |
| `/assets/*` | `public, max-age=31536000, immutable` | 文件名带内容 hash，内容变了名字就变，可以永久缓存 |

另外构建时会把时间戳（本地时区）写进产物，设置面板底部能看到「构建版本」，
用来确认当前页面到底是哪一次构建。

实现：`app/main.py` 里的 `LongCacheStatic` 与 `NO_STORE`。
注意 Starlette 的 `file_response` 是**同步**方法，写成 async 会 500。
