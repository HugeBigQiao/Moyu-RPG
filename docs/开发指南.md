# 开发指南

## 1. 环境

- Python 3.14+（项目要求；本机没装也没关系，`uv sync` 会自动准备解释器）
- Node 20+（前端构建；前端是 TypeScript，类型检查用 vue-tsc）
- Windows / Linux / macOS 均可：后端无平台相关依赖，SQLite 默认库
- 数据库不用装：默认 SQLite

```powershell
cd backend;  uv sync
cd ../frontend; npm install
```

## 2. 跑起来

```powershell
# Windows 一键
.\start.bat

# Linux / macOS 一键（首次先 chmod +x start.sh）
./start.sh

# 或分开（两个平台相同）
cd backend;  uv run python run.py            # 8888
cd frontend; npm run dev                     # 5173，/api 代理到 8888
```

Linux 备注：

- 首次 checkout 的文件没有可执行位，`chmod +x start.sh` 或直接 `bash start.sh`。
- UI 冒烟默认用 Windows 自带的 Edge 通道；Linux 上指定
  `PLAYWRIGHT_CHANNEL=chrome` 或 `PLAYWRIGHT_EXECUTABLE=/usr/bin/chromium`。
- 中文字体走 `Noto Sans CJK SC` 回退；没装的话中文会落到系统默认字体，能看但观感不同。

## 3. 测试

```powershell
cd backend
uv run pytest -q                     # 169 个单测
uv run python scripts/api_smoke.py   # 28 项接口冒烟（要先起服务）
uv run python scripts/smoke.py mirror # 不开服务，直接跑一局引擎

cd ../frontend
npm run typecheck                    # vue-tsc --noEmit，类型检查（构建不查类型）
node scripts/ui_smoke.mjs            # 52 项无头浏览器检查
```

> 中文 Windows 控制台是 GBK：`scripts/smoke.py` 会打印 `▶`，输出被重定向时会
> `UnicodeEncodeError`。先 `$env:PYTHONIOENCODING='utf-8'` 再跑；脚本本身也该用
> `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` 兜底。

## 4. 改设定（最常见的事）

设定全在 `backend/data/content/*.json`。改完不用重启：

```powershell
curl -X POST http://127.0.0.1:8888/api/admin/reload
# 或者浏览器控制台：fetch('/api/admin/reload',{method:'POST'}).then(r=>r.json()).then(console.log)
```

### 在界面里改（不用打开编辑器）

档案页每一类右上角都有「＋ 新增 / 编辑 / 删除」：填表保存，直接写回 `backend/data/content/*.json`，
写完自动重载。适合加城市、改文案、补事件；复杂结构（比如剧本的 `scenes`）仍然建议直接改 JSON。

删除会被引用拦住：比如删一座还有任务发案、还有人物登记的城市，会直接告诉你谁在用。

### 加一个事件

编辑 `content/events.json` 的 `events` 数组：

```json
{
  "id": "ev_new_thing",
  "name": "事件名",
  "grade": 3,
  "scope": "general",
  "industries": ["medical"],
  "text": "一句话背景。",
  "hook": "这个人为什么牵涉进来。",
  "traits": ["胆大"],
  "weight": 15
}
```

规则：`grade` 1–4（甲→丁）；`grade ≤ 2` 必须是 `scope: "mission"` 并写 `missions`；
`traits` 里的名字必须在 `traits.json` 里存在。

### 加一座城市

`content/world.json`：

- `cities` 里加条目（`tier` 必须存在于 `tiers`，`industries` 必须是已知行业 id）
- `city_geo` 里加经纬度 `"城市id": [纬度, 经度]`
- `city_factions` 里加当地势力

### 加一个固定剧本

1. `content/scenarios.json` 里加场景流（`investigate` / `combat` / `choice` / `ending`）
2. `content/missions.json` 里加任务条目，`scenario_id` 指向它，`cities` 指定可发案城市

### 加一件装备 / 一条特性

- 装备：`content/equipment.json`
- 特性：`content/traits.json`（`effect` 的键要和 `engine/sheet.py` 的算法对上）

## 5. 加一个接口

1. `app/api/schemas.py` 加请求体（如果需要）
2. 在对应模块（`archive.py` / `game.py` / `characters.py` / `sessions.py`）加路由：

```python
@router.get("/something/{id}")
async def api_something(id: str, db: AsyncSession = Depends(get_db)):
    ...
```

3. 前端 `src/shared/api.js` 里加一行封装
4. `python scripts/api_smoke.py` 补一条断言

## 6. 改数据库结构

```powershell
cd backend
# 1. 改 app/models/entities.py
# 2. 生成迁移
uv run alembic revision --autogenerate -m "说明"
# 3. 检查生成的脚本，非空列必须带 server_default
# 4. 应用
uv run alembic upgrade head
```

**踩过的坑**：`--autogenerate` 给已有表加非空列时不写默认值，
生产数据上会直接 `NotNullViolation`。正确写法是

```python
op.add_column("t", sa.Column("x", sa.Integer(), nullable=False, server_default="0"))
op.alter_column("t", "x", server_default=None)
```

## 7. 前端

TypeScript + Vue 3。前端按功能分区，不再分 views / components：

```
src/app/       壳（App.vue、router.ts、顶栏·设置·遮掩）
src/areas/     一个目录一个功能：HomeView · archive/ · play/
src/shared/    跨区域复用：api.ts · types.ts · settings.ts · stealth.ts · flash.ts
```

- **类型**：接口响应结构写在 `src/shared/types.ts`，`api.ts` 的方法都带返回类型；
  组件用 `defineProps<{...}>()` / `defineEmits<{...}>()`，不写运行时 props 对象。
- **改接口时**：先改 `shared/types.ts`，再跑 `npm run typecheck`，最后 `npm run build`。
- `assets/china.ts` 由 `backend/scripts/build_china_map.py` 生成，别手改。

- **放哪里**：新增或修改一个功能，先找 `src/areas/<区域>/`；页面、页内组件、字段规格都放一起。
  只有被第二个区域用到的东西才提到 `src/shared/`；顶栏/设置这类全站壳放 `src/app/shell/`。
- 新页面：`src/areas/<区域>/XxxView.vue` + `src/app/router.js` 加一条路由（`meta.title` 会显示在顶栏）
- 新接口：`src/shared/api.js` 加方法
- 设置项：`src/shared/settings.js` 加字段，`src/app/shell/SettingsPanel.vue` 加控件，CSS 里用 `data-theme` / `var(--base-size)`
- 主题：`src/style.css` 里 `:root[data-theme='xxx']` 覆盖变量即可
- 配色：组件里**不要写死 hex**。新颜色先加语义变量（`--surface-btn` / `--heading` / `--text-body` 这类），
  再在 `:root`、`[data-theme='light']`、`[data-theme='ink']` 各赋一次；写死深色会让浅色主题出现黑块（踩过）

## 8. 提交前检查

```powershell
cd backend;  uv run pytest -q
cd ../frontend; npm run typecheck; npm run build
```

- 新内容要能通过 `uv run python -c "from app.content._store import reload_all; print(reload_all())"`
- 不提交 `backend/.env`、`backend/data/*.db`、`frontend/dist/`
- 提交信息用「动词: 说明」的格式

## 9. 注释规范

每个 Python 模块开头固定三段：

```python
"""一句话说这个文件是什么。

职责：
    这个文件负责什么（一句话，具体）。
为什么需要：
    不写它会怎样（说清动机，不写「为了规范」）。
上下游：
    上游：谁给它数据；下游：它把数据交给谁。
"""
```

函数 docstring 固定三段：

```python
def resolve(roller, skill, value, modifier=0):
    """掷一次 d100 检定。

    参数：
        roller：随机源，必须带种子才能复现。
        skill：技能名，用于展示与日志。
        value：技能值（0–99），检定的基准。
        modifier：环境/属性对抗带来的修正。
    为什么需要：
        所有判定必须共用同一套阈值，各写各的会导致数值不一致。
    输出：
        CheckResult（掷骰结果、目标值、成功等级）。
    """
```

块级注释只写「这段在处理什么」，不复述代码：

```python
# 先按城市等级截断事件数，再按等级权重抽，避免小城抽出十条甲级
```

前端组件同理：`<script setup>` 开头写「这个组件负责什么、谁在用」，
复杂计算用一行注释说明意图。
